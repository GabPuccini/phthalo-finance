# Phthalo Finance

A personal net worth and savings tracker for one person. It is a Progressive Web App
built from plain HTML, CSS and vanilla JavaScript modules. There is no build step, no
bundler, no framework and no runtime dependency of any kind.

Everything you record stays in your own browser. Nothing is uploaded, there is no
account to create, and the only network requests the app ever makes are the optional
unit price lookups, which are allowed to fail without affecting anything.

## Running it locally

ES modules and service workers both need a real web server, so opening `index.html`
straight off the disk will not work. Serve the folder instead:

```sh
cd phthalo-finance
python3 -m http.server 8000
```

Then open <http://localhost:8000> in a browser.

To check that it also works from a subfolder, which is how GitHub Pages will serve
it, run the server one directory up instead:

```sh
cd ..
python3 -m http.server 8000
```

and open <http://localhost:8000/phthalo-finance/>. Every path in the project is
relative, so both work.

## Running the tests

```sh
node --test
```

That needs nothing installed beyond Node itself. It takes about five seconds, most of
which is one test that genuinely waits out the five second price lookup timeout. It also
fails if the app's files have changed since `sw.js` was last stamped, see Deploying below.

You can also open <http://localhost:8000/tests.html> to run the same assertions in a
browser, including on your phone. Both runners load the cases from `tests/cases.js`,
so the two cannot drift apart.

## File structure

```
phthalo-finance/
  index.html            the app shell, all paths relative
  tests.html            the same test assertions, run in the browser
  styles.css            both themes and every style, mobile first
  manifest.json         PWA manifest, start_url and scope both "./"
  sw.js                 service worker, one cache per release
  .nojekyll             stops GitHub Pages processing the files

  src/
    logic.js            every calculation and every colour, pure, no DOM
    plan.js             the long term plan, worked out month by month, pure
    app.js              the screens, calls logic.js and plan.js for every number
    charts.js           the charts, hand written inline SVG
    icons.js            the category badges and interface icons
    storage.js          localStorage, backups, export and import
    prices.js           the optional live price lookup
    seed.js             the default accounts and the demo data

  tests/
    cases.js            the assertions, shared by both runners
    logic.test.js       the Node runner

  tools/
    stamp-sw.mjs        stamps CACHE_VERSION in sw.js before a deploy
    browser-smoke.mjs   drives the real app in a browser
    make-icons.py       draws and writes the PNG icons

  icons/                real PNG files, generated by make-icons.py
```

The split that matters is `logic.js` against `app.js`. Every calculation lives in
`logic.js` as a pure function with no access to the DOM, to storage, to the network or
to the clock. Anything that needs to know today's date takes it as an argument. That is
what makes the sums testable, and it is why `tests/cases.js` can check them without a
browser anywhere in sight.

## How your data is stored

Everything sits in `localStorage` under one key, `phthalo.finance.v1`, with a rolling
copy of the last known good state under `phthalo.finance.v1.backup`.

Two rules keep the numbers honest:

* **Money is always an integer number of pence.** Pounds only ever appear at the moment
  something is displayed. This is what stops the rounding drift that spoils most simple
  finance apps.
* **Dates are always `YYYY-MM-DD` strings**, never `Date` objects or timestamps. This is
  what stops the off by one day bug that timezone conversion causes.

The saved object carries a `schemaVersion`. When an older version is loaded it is
upgraded by a migration function rather than being thrown away. Version 2 added the
long term plan, saved as `plan` in the same object, so it travels with every backup.

Net worth history is rebuilt by walking the whole transaction list in date order every
time it is drawn. It is never stored as a running snapshot. That is why editing or
backdating an old entry correctly rewrites the entire line rather than only affecting
today.

### A warning worth repeating

iOS Safari can clear the storage of a website you have not opened for a few weeks,
unless it has been added to the home screen. The app says so once on a first run on
iOS, and reminds you to export a backup if you have not done so for 30 days. Export
files are plain JSON and importing one restores everything exactly.

## The screens

* **Home.** Net worth, large, top left, with the change over the chosen period and a line
  you can drag a finger along to read any day. Below it, every account as a card with its
  category badge, and a progress bar for any account with a goal. The add button sits in
  the corner.
* **An account.** Tap a card. With a goal you get a ring showing how far you are, what is
  saved and what remains, the target date and how long is left, and what you need to put
  in each day, week and month to arrive on time. Records lists every entry; tap one to
  change or delete it. Below the goal sit the account's own history, its unit price if it
  has one, when a debt clears, and the controls to reorder, archive or delete it.
* **Insights.** The analysis charts, which you can switch on and off and reorder.
* **Plan.** A long term plan, worked out month by month and checked against your real
  accounts. See the next section.
* **Activity.** Every entry across every account, newest first.
* **Settings.** Backups, the theme, prices, and the demo data.

## The plan

The Plan tab holds one long term plan. A plan is a list of lines, one per pot of money
or debt, each with its balance at the start, a growth rate or an interest rate, and the
amounts that go in each month. An amount can start and stop on a month, when a debt is
paid off, or at the house purchase, and can stop filling a pot at a set balance. Money a
line cannot take, because it is full, closed or over the Lifetime ISA limit, moves on to
the line it names, and a debt's payment does the same once it is cleared.

The engine in `src/plan.js` runs every month in the same order: growth, then debt
interest and payments, then the monthly amounts, then the purchase. A Lifetime ISA takes
at most £4,000 a tax year, counted from April, with the 25% bonus added as the money
goes in. At the purchase all of the Lifetime ISA goes toward the price, because that is
the only thing it can be spent on. The deposit pots top the deposit up to the lender's
minimum and pay the buying costs, and whatever they cannot cover comes out of the line
named for what is left over, going below zero if it has to, so the net worth stays
honest.

Each line can be linked to one or more accounts. The screen then shows:

* whether your linked accounts are ahead of, behind or on the plan today;
* a chart of the plan, where you have actually been, and a forecast that runs the same
  rules from next month starting from your real balances;
* each milestone, such as a loan paid off or a pot filled, with its planned month and
  the month the forecast now gives it;
* the purchase as it now stands, with a warning when the cash will not cover it;
* every line at the end of any plan year, against the forecast.

Set up the house plan builds the ten year plan to a house in October 2031, linked to the
default accounts. Every figure in it can be changed on the tab.

## How it looks, and why

The dark theme is near black and neutral rather than tinted, with crisp white text and one
accent colour, violet, used for everything you can tap and for any chart that has a single
series: the net worth line, the goal rings and progress bars, the account bars. A light
theme mirrors it. The app follows your phone's setting, and uses dark when there is none.

Colour does one job in each place it appears, and means the same thing everywhere:

* **Violet** is the interface, and single series data.
* **Green and red** mean money in and money out, gains and losses, ahead and behind.
  Red is also the debt.
* **Five category colours** (orange crypto, teal property savings, blue investments,
  amber precious metals, pink cash) appear only on the allocation bar and on the round
  badge beside each account, so a colour always means a category.

None of that was picked by eye. Every text colour was measured against every background
it sits on in both themes and reaches WCAG AA, 4.5 to 1. The category colours come from a
documented palette that was run through a colour vision check, and the allocation bar
keeps them in one fixed order, chosen because every pair of neighbours stays apart for
people with colour blindness as well as full colour vision. `TESTING.md` has the numbers,
and a test fails if `styles.css` ever drifts from the colours that were measured.

The charts follow a short list of rules: the most important number top left, one message
per chart, bar axes from zero, bars sorted by value, thin marks with a rounded data end,
labels on the chart rather than in a separate key wherever they fit, no heavy gridlines or
shadows, detail on tap, a title that states the finding rather than naming the chart, a
table of the numbers behind every chart one tap away, and never a blank chart.

## Deploying

```sh
node tools/stamp-sw.mjs
node --test
git push
```

An installed copy only notices a new release when `sw.js` changes. The stamp sets its
`CACHE_VERSION` from a hash of every file the app caches, so it changes exactly when they
do, and `node --test` fails if you forget. The service worker then serves the page and its
code from one cache per release, so a phone can never pair a new page with old scripts.
`SETUP.md` has the full steps.

## Five sensible future additions

1. **A currency setting.** Everything is in pounds today. A per account currency, with
   totals converted at a rate you set, would cover savings held abroad.
2. **Recurring entries.** A monthly transfer that posts itself, so regular saving does not
   need typing in every month.
3. **Plan scenarios.** Keep two versions of the plan side by side, for example the
   Lifetime ISA at its maximum against more cash for the buying costs, and compare them
   on one chart.
4. **Encrypted backups.** A passphrase on the export file, so a backup can sit in cloud
   storage without the contents being readable.
5. **A yearly review.** Money in, money out, growth and the biggest movers for a chosen
   year, on one page worth printing.
